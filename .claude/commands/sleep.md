# /sleep — принудительный sleep ритуал

Используется когда:
- Owner написал «сохраняемся», «закрываем сессию», «end», «save» или похожее.
- Закрыт значимый пункт `NEXT.md`, и сессия естественно завершается.
- Перед длинной паузой (owner уходит на день/неделю).

## Что делать (строго по порядку)

### 1. Обнови `D:\AI Projects\CMOS\STATUS.md`
- Поменяй «Дата последнего обновления» на сегодняшнюю (YYYY-MM-DD).
- В блок «Что сделано в последнюю сессию» — внеси конкретные артефакты:
  - Имена созданных/изменённых файлов.
  - Принятые архитектурные решения (со ссылкой на ADR, если он создан).
  - Закрытые блокеры из ROADBLOCKS.
- Скорректируй «Текущая фаза» и «% готовности».
- Обнови «Где мы в roadmap» если изменилось.
- Сохрани лимит «1 экран максимум» — если разрослось, выкинь старые детали (они уже в conversation-log).

### 2. Обнови `D:\AI Projects\CMOS\NEXT.md`
- Удали закрытые пункты.
- Добавь новые пункты, появившиеся в этой сессии.
- Перепроверь приоритеты (1 = ближайший).
- Сохрани лимит «1 экран максимум».

### 3. Создай новый файл `D:\AI Projects\CMOS\docs\09-conversation-log\YYYY-MM-DD-<topic>.md`
- Формат имени: `2026-05-26-scope-and-automation.md`. `<topic>` — короткий (2-4 слова) кебаб-кейс, отражающий главную тему.
- Содержание:
  - **Контекст:** что было до этой сессии (1 абзац).
  - **Что сделано:** список артефактов (имена файлов, тип изменения).
  - **Ключевые решения:** что и **почему именно так**. Это самое важное — рассуждение, а не результат.
  - **Открытые вопросы:** что осталось нерешённым, ссылка на ROADBLOCKS.
  - **Следующий шаг:** ссылка на NEXT.md.
- Этот файл — основной wake-up артефакт. Пиши его на русском, плотно, без воды.

### 4. Если приняты архитектурные решения → новый ADR
- Найди следующий свободный номер в `docs\02-decisions\` (сейчас последний — ADR-010).
- Скопируй `000-adr-template.md` как `ADR-NNN-<slug>.md`.
- Заполни: status (Accepted), context, decision, consequences, alternatives considered.
- ADR пишется **на английском**.

### 5. Если возникли открытые вопросы → обнови `ROADBLOCKS.md`
- Добавь Q-номер по порядку.
- Структура: Контекст / Кандидаты / Зависит от / Решается в.

### 6. Финальный отчёт owner'у
Одним абзацем доложи:
- Какие файлы обновлены.
- Какие новые файлы созданы (с путями).
- Сколько ADR добавлено, какие.
- Можно ли safe закрывать окно (yes/no, если no — что блокирует).

## Что НЕ делать

- Не пропускай ни один из шагов 1-3 — это hard-минимум sleep-ритуала.
- Не пиши conversation-log «постфактум» через неделю — теряется контекст рассуждения. Только в конце сессии.
- Не удаляй старые conversation-log файлы — они history.
- Не перезаписывай ADR с тем же номером — ADR immutable, новое решение = новый ADR (с supersedes-ссылкой).
