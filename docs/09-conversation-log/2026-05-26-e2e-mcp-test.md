## Ключевые решения

1. **Тест spawns binary, не unit-тестирует handler напрямую.** Это настоящий e2e: запускается `cmos-cli mcp --root <tmpdir>`, общение через stdin/stdout. Проверяет весь стек от JSON-RPC parsing до SQLite persistence.

2. **assemble_context gracefully handles missing Ollama.** Если Ollama не запущен или модель не скачана — возвращает ошибку через isError=true, тест это принимает как ожидаемое поведение. Не блокирует CI.

3. **Unknown tool → SDK возвращает CallToolError, не top-level JSON-RPC error.** Тест проверяет оба варианта (resp["error"] || resp["result"]["isError"]).

## Ответы owner'у

### Как тестировать MVP

- **Сейчас:** `cargo test --workspace` (95 тестов), MCP server через stdin, bootstrap на реальном проекте.
- **Полноценно:** подключить к Claude Desktop/Code как MCP server, сделать bootstrap на Django marketplace, работать как обычно — Claude будет использовать cmos_* tools.
- **Token Analytics** (следующий milestone) покажет конкретные цифры экономии.

### GUI в MVP

- **Да, входит** (Milestone 5). Tauri + React.
- **Что будет:** sidebar (projects), memory inspector (L1-L4), memory stats, token analytics dashboard.
- **Чего не будет:** редактирование памяти, time travel, counterfactual mode, настройки модели.
- GUI — DevTools-style наблюдаемость, не панель управления.
