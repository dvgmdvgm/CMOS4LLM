# Scope: V2 — Breakthrough Features

> **Goal of V2:** turn CMOS from a personal-power tool into a team-grade substrate, and add the features that empirically advance the field of LLM-driven development.
>
> V2 = V1 + the items below. Locked-in only after V1 is delivered and stable; do not pull these forward.

---

## V2 features (with acceptance)

### V2.A. Constrained decoding via local inference proxy

- [ ] Optional local proxy server interposing between CMOS and inference (cloud or local).
- [ ] Grammar-based decoding: BNF / EBNF / Lark grammars enforce structure.
- [ ] JSON-schema decoding: stricter than provider's structured output (full JSON Schema support including `$ref`, `oneOf`, `allOf`).
- [ ] Custom DSL hooks: project-specific token-mask rules at sampling time.

**Acceptance:** marketplace migration generation enforced via grammar produces zero structurally-invalid migrations across 100 generations.

### V2.B. JetBrains plugin

- [ ] PyCharm + IntelliJ IDEA + WebStorm support, embedding the same web core as JCEF webview.
- [ ] Feature parity with VS Code extension (V1.G).

**Acceptance:** JetBrains user does a full work-day on the marketplace identically to VS Code user.

### V2.C. Manager / shared view

- [ ] Lower-density read-only surface tailored for non-technical reviewers.
- [ ] Project-health summary: token budget vs cap, drift trend, episode throughput, decision-log highlights.
- [ ] Shareable URLs (read-only links with optional expiry).

**Acceptance:** manager-role user can answer "how is the project's quality trending?" in < 5min using only this view.

### V2.D. Multi-user collaboration

- [ ] User accounts with project-level ACLs (read / contribute / admin).
- [ ] Attribution: every fact, episode, policy, DNA edit carries an actor (human or LM with prompt-id).
- [ ] Comments on episodes, decisions, drift events.
- [ ] Shared CMOS instance deployable as a service (single-tenant on a team server is the target — multi-tenant SaaS is Future).

**Acceptance:** team of 3 collaborates on the marketplace through a shared CMOS instance for 30 days; full audit trail; zero cross-user leakage.

### V2.E. Cross-project memory transfer

- [ ] Explicit "import" operation: take a fact / policy / episode / DNA section from project A and inject into project B.
- [ ] Provenance preserved: origin project_id retained as metadata; cross-project lineage visible.
- [ ] DNA-template marketplace (proto): owner can publish a project's DNA as a reusable template.

**Acceptance:** owner imports the marketplace's `webhook_idempotency` policy into a side-project's CMOS; provenance link to original incident-2025-04-12 is retained and clickable.

### V2.F. Auto-policy promotion

- [ ] Drift trends crossing configurable thresholds auto-create draft policies.
- [ ] Auto-promotion respects evidence requirement: drafts include the violation pattern + sample violations as evidence.
- [ ] Owner approval still required (no silent rule changes).

**Acceptance:** simulate 60 days of drift activity; ≥80% of trends crossing threshold result in surfaced draft policies that owner finds materially correct.

### V2.G. A/B policy testing in production

- [ ] Policy tags allow assigning sessions to test groups.
- [ ] Per-group telemetry: drift rate, token cost, episode outcome correlation.
- [ ] Statistical-significance display when sample size is sufficient.

**Acceptance:** owner runs a 14-day A/B comparing two variants of a soft policy; significance verdict emitted at end with sample size and effect size.

### V2.H. Cost dashboard for teams

- [ ] Per-user / per-project / per-area budgets with alerting.
- [ ] Cost attribution: who triggered which inference; aggregate spend.
- [ ] Forecasting: "at current rate, monthly spend = $X."

**Acceptance:** team-mode CMOS produces a weekly cost report with no manual aggregation needed.

### V2.I. Self-optimization layer

- [ ] **Cognitive profiler**: instruments retrieval / assembly / Sub-LM / cloud paths; produces flame-graph-style report.
- [ ] **Token waste detector**: identifies retrievals with low utility (high tokens, low downstream relevance score).
- [ ] **Adaptive memory hierarchy**: promotion / demotion thresholds tuned automatically per project usage pattern.
- [ ] **Semantic redundancy detector**: flags duplicate-meaning facts in L4 for owner to reconcile.

**Acceptance:** running on the marketplace, self-optimization layer reduces token cost a further 1.5–3× over V1 baseline within 30 days of operation, without quality regression.

## Definition of Done for V2

1. Every V1 DoD condition still holds.
2. All V2.A–V2.I acceptance criteria met.
3. Team-of-3 deployment in real use for 30 days; full audit trail; no data-isolation incidents.
4. Self-optimization layer demonstrates measured improvement on production workload.
5. Documentation parity: every V2 component spec exists and is current.
