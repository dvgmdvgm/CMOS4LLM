# Scope: V3 — Frontier

> **Goal of V3:** features that require research-grade work, partnerships, or experimental components. Reaching V3 means CMOS is publishable as substrate-of-record in the LLM-substrate space.
>
> Items here are explicitly **research-coupled**. Acceptance criteria include "publishable result," not just "feature works."

---

## V3 features (research-coupled)

### V3.A. Persistent KV-cache infrastructure

- [ ] Sticky routing layer that pins repeated prompts to the same inference node.
- [ ] Custom inference proxy with paged-attention KV persistence (vLLM-based or equivalent).
- [ ] Cross-session KV reuse: prompt caching TTL extended from minutes to hours.
- [ ] Provider partnership: works with at least one major provider (Anthropic / OpenAI / Gemini Enterprise) or with self-hosted open-weight models.

**Acceptance:** measured cache-hit rate on stable prefix > 95% over a 24h period; effective per-call latency reduced ≥30%; aggregate token cost reduced a further 2–5× over V2.

**Research output:** technical paper or detailed engineering report on practical KV persistence at scale.

### V3.B. LoRA-as-memory

- [ ] Pipeline distilling a project's L4 into a LoRA adapter periodically (weekly / monthly).
- [ ] Adapter as a "compressed model of the project" — used for Sub-LM speedups on project-specific tasks.
- [ ] Hybrid mode: adapter handles routine queries; cloud LLM handles novel reasoning.

**Acceptance:** adapter trained on 6 months of marketplace activity; on routine queries it matches or exceeds non-adapted Sub-LM quality; per-query latency < 50% of cloud-LLM baseline.

**Research output:** measurement of when distillation saturates, when adapters become stale, retraining cost.

### V3.C. Symbolic-neural hybrid reasoning

- [ ] SMT solver (Z3 or equivalent) integrated as a constraint backend.
- [ ] Logical invariants expressible as Z3 formulas (e.g., "if X then Y must hold").
- [ ] Pre-generation feasibility checks; counterexample-driven repair loop.
- [ ] Domain-specific logic compilable from policies (e.g., "money is conserved across order transitions").

**Acceptance:** at least 10 marketplace invariants expressed in Z3; compiled checker catches synthetic violations and produces minimal counterexamples in < 1s each.

**Research output:** investigation of which classes of project invariants are solver-amenable vs. fundamentally fuzzy.

### V3.D. Latent memory persistence research

- [ ] Experimental track using state-space models (Mamba-Hybrid, RWKV-class) as memory substrate.
- [ ] Investigation: can hidden state be exported, version-controlled, transferred across sessions?
- [ ] Open-weight prototype on a smaller model.

**Acceptance:** prototype demonstrates non-trivial cross-session memory via hidden state on at least toy-scale tasks; identifies which architectural changes are required for production-scale.

**Research output:** paper or technical report on the practical bounds of latent persistence in current architectures.

### V3.E. External attention systems

- [ ] Architectural prototype: attention layers querying external memory (RETRO-style or memorizing transformer-style) instead of relying solely on context window.
- [ ] Open-weight model trained or fine-tuned to use CMOS as an external attention source.

**Acceptance:** prototype on a small model demonstrates fundamentally different scaling properties than vanilla attention; reproducible on community hardware.

**Research output:** publishable comparison vs. vanilla long-context.

### V3.F. Distributed cognition

- [ ] Multiple agents coordinating through CMOS as shared substrate.
- [ ] Shared L4, per-agent L1/L2/L3.
- [ ] Conflict-resolution protocols for concurrent edits.
- [ ] Demonstrated in a multi-agent dev workflow (e.g., parallel implementer + reviewer agents).

**Acceptance:** 3-agent setup completes a non-trivial marketplace task with explicit handoff; coordination overhead measured and acceptable.

**Research output:** empirical study of multi-agent coordination via shared semantic memory.

## Process for V3

V3 is research-coupled, which means:

- Every feature has a research log alongside the implementation.
- Each feature ships only if a publishable / shareable artifact (paper, post, dataset, benchmark) accompanies it.
- Negative results are also valid V3 outputs — failure to deliver X with conclusions about why is acceptable.
- Failure to advance any V3 feature in 12 months → reassess: drop, postpone, or escalate.

---

## Out of V3

Anything not listed here is V2 or earlier (already shipped) or Future (not yet scoped). Specifically:

- Multi-tenant SaaS — Future, not V3.
- Mobile UI — Future, not V3.
- Federated memory — Future.
- Plugin SDK — Future.

---

## Definition of Done for V3

1. Every V2 DoD condition still holds.
2. At least 3 of V3.A–V3.F have shipped with research-output artifacts.
3. CMOS has been presented or published as a substrate (talk, paper, or detailed public technical writeup) at least once.
4. The owner-driven feedback loop (CMOS used on marketplace daily) continues uninterrupted through V3 changes.
