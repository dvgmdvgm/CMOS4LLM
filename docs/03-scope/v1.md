# Scope: V1 — Release Candidate

> **Goal of V1:** make CMOS the daily-driver tool the owner uses on the Django marketplace without compromise. Everything promised in design lands; nothing planned for V1 is deferred quietly.

V1 = MVP + the items below. Each feature has acceptance criteria. The system is V1 only when **all** are met.

---

## V1 features (with acceptance)

### V1.A. Drift Monitor GUI

- [ ] Drift events written to L4 by Sub-LM background scan on every generated diff.
- [ ] Drift Monitor screen: timeline of violations by category (style / arch / policy / anti-pattern).
- [ ] Per-violation card: rule, file:line, detected timestamp, snippet; actions: view / fix-with-LM / exempt-with-reason / snooze.
- [ ] Trends panel: most-violated rules, most-frequent violator files, "best-behaved" areas.
- [ ] **Suggested rules**: when a soft pattern is violated ≥10× in 30 days, surface as candidate hard policy with one-click promote.

**Acceptance:** generate 100 diffs over 30 days of work; every hard-invariant violation appears in Drift Monitor within 60s of generation; trends panel surfaces top-3 most-violated rules.

### V1.B. DNA Editor GUI

- [ ] Versioned editor: every save is a new DNA version; diff viewer between any two versions.
- [ ] Section navigation (Identity / Architecture / Hard / Soft / Style / Forbidden / Critical).
- [ ] Token-budget meter (max 20K).
- [ ] Evidence links: click an invariant's evidence_refs → opens incident / decision / PR.
- [ ] Suggested rules pane: drift trends → one-click "promote to invariant" creates draft invariant; user must approve before publish.

**Acceptance:** edit DNA, publish v15; rollback to v13; diff v13↔v15 visible. Drift-suggested rule appears in pane when triggered.

### V1.C. Knowledge Graph Viewer

- [ ] Cytoscape.js graph; modes: Domain / Code-symbols / Decisions-evolution / Module-deps / Combined.
- [ ] Focus + depth (1–5) + force/hierarchical layout.
- [ ] Selected node panel: type, source, used in N episodes, active policies, [pin / expand neighbors / find code].
- [ ] **Decisions/evolution mode**: temporal timeline visualization; supersession edges shown.

**Acceptance:** loaded with the marketplace project, all four base modes render < 2s for graphs up to 50K nodes; switching modes does not refetch data.

### V1.D. Episodes Browser GUI

- [ ] Episode list with filter / sort / search.
- [ ] Episode detail: problem, approach taken, approaches rejected (+ rationale), lessons, files touched, resulting policies, similar episodes (with sim score).
- [ ] Lessons mining: when an episode completes, Sub-LM extracts lessons → episode card; user can edit.
- [ ] "Replay similar" — find episodes ≥0.85 similarity to a current task, inject lessons into context.

**Acceptance:** completing 5 marketplace tasks produces 5 episode entries with non-empty lessons; starting a 6th similar task surfaces the relevant prior episode in the inspector before inference.

### V1.E. Policy Manager GUI

- [ ] Tabular view of all policies; bulk operations: enable/disable groups, change tier, edit scope.
- [ ] **A/B testing groups**: tag policies into experiment groups; per-group enable/disable for measurement; link to counterfactual mode.
- [ ] Per-policy detail: usage in N inferences, violations N in 30d, evidence_refs.

**Acceptance:** seed 50 policies; bulk-disable a group; verify drift report reflects the change for the next inferences.

### V1.F. Counterfactual Mode (per ADR-008)

- [ ] Counterfactual setup panel: choose scope (last N inferences | tag | project area), variation (policy add/remove/modify | DNA version | retrieval strategy | model), execution mode (Sub-LM-only default | cloud opt-in with cost preview).
- [ ] Background worker queue (low priority, never blocks live path).
- [ ] Comparison view: side-by-side original vs counterfactual; assembled-context delta; response delta (cloud mode); drift-verdict delta.
- [ ] Entry points: "Counterfactual ▾" on past inferences, "test this change" in DNA Editor, "what would happen?" per policy.

**Acceptance:** select 30 inferences; create counterfactual disabling policy P; results render < 5min on owner's hardware (Sub-LM-only mode); delta correctly highlights affected outputs.

### V1.G. VS Code Extension

- [ ] VS Code extension hosting the same web core as a webview panel.
- [ ] Talks to CMOS daemon over the same WebSocket protocol.
- [ ] Side-panel layout adapted (vertical-tall) for IDE constraints.
- [ ] Auth bootstrap: extension registers with daemon on first launch; token in VS Code SecretStorage.
- [ ] Quick actions: "Open Live Inspector for this turn", "Show drift in current file", "Pin this episode".

**Acceptance:** marketplace developer can do a full work-day inside VS Code with CMOS extension as their only CMOS UI; functions equivalent to desktop shell.

### V1.H. L5 Archival (full)

- [ ] Cold storage backend: object-store-compatible (S3 API) + local FS fallback.
- [ ] Cold KG snapshot: periodic flatten of L4 to immutable parquet/lance with timestamp.
- [ ] Decay policy: aged inactive episodes → digest replacement (full content compressed to 1–2 lines).
- [ ] Archival query path: any historical fact retrievable in < 1s p95.

**Acceptance:** simulate 6 months of activity; L5 size grows < 1 GB; "what did we decide about X 5 months ago?" returns the original decision in < 1s.

### V1.I. Compressed Cognition Blocks

- [ ] Sub-LM detects "this episode produced reusable insight" trigger.
- [ ] Generates compressed block (200–500 tokens) representing the reasoning artifact.
- [ ] Block stored in L4, indexed for similar-task retrieval.
- [ ] On similar future task, block injected into prompt instead of replaying entire reasoning.

**Acceptance:** 10 representative tasks produce blocks; on subsequent similar tasks, measured cloud-token usage drops ≥50% vs first occurrence (replay vs reuse).

### V1.J. Differential Retrieval

- [ ] Retrieval Router tracks per-session "already returned" set; suppresses duplicate items in subsequent retrievals unless updated.

**Acceptance:** in a 30-turn session, measure context-overlap reduction ≥40% vs MVP baseline.

### V1.K. Constraint Hoisting (basic)

- [ ] Structured-output mode (JSON schema) enforced via provider's structured-output API where available.
- [ ] Schema-invariants (must-have fields, type constraints) checked pre-emptively rather than via post-hoc repair.

**Acceptance:** for tool-call workflows, measured repair-loop frequency drops ≥80% vs MVP.

### V1.L. Memory Heatmap

- [ ] Visualization of L4 items colored by access frequency.
- [ ] Hot (top 20%) red; cold (never accessed in N days) grey.
- [ ] One-click "demote unused" to flag candidates for L5 demotion.

**Acceptance:** loaded with marketplace L4, heatmap renders <2s; demotion suggestions reduce hot-path retrieval surface ≥30%.

### V1.M. Bootstrap pipelines: second project type

- [ ] Node/TypeScript bootstrap pipeline (parallel to Django): tsserver-based AST sweep; package.json + lockfile parsing; Express/Next/NestJS framework detection; tests-layout detection.

**Acceptance:** owner picks a Node/TS project from their portfolio; bootstrap completes; produces functional L4 equivalent in shape to the Django bootstrap output.

## Token-reduction targets at V1

Composite reduction (cloud tokens vs simulated baseline) on representative tasks:

- Read-only / informational queries: 20–100×.
- Code modification (typical): 8–25×.
- Architectural reasoning (rare, hard): 3–8×.
- **Aggregate weighted average across owner's task mix: ≥10×** — this is the V1 success metric.

## Definition of Done for V1

1. Every MVP DoD condition still holds.
2. All V1.A–V1.M acceptance criteria met.
3. Owner has used CMOS daily on the Django marketplace for ≥30 working days without falling back to direct LLM access for any non-trivial task.
4. Aggregate token reduction ≥10× across measured task mix.
5. A senior engineer unfamiliar with the project can be onboarded to CMOS in 1h via README + STATUS + NEXT + recent conv-log + relevant ADRs.
6. Documentation parity: every V1 component has a spec in `docs/04-components/`; every GUI screen has a spec in `docs/05-gui/`; bootstrap is documented for Django and Node/TS.
